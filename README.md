# 五子棋 AI 助手（gomoku.com）

为 [gomoku.com](https://gomoku.com/zh-cn/online-battle/) 的五子棋 / 连珠提供 AI 落子提示或自动下棋。

支持的页面：

| 页面 | 地址 | 规则 |
|---|---|---|
| 在线对战 | `/zh-cn/online-battle/` | 五子棋（五连及以上获胜） |
| 在线对战（连珠） | `/zh-cn/renju/online-battle/` | 连珠（黑棋禁手：长连、四四、三三） |
| 单人游戏 | `/zh-cn/single-player/` | 五子棋 |

其他语言版本的同类页面（如 `/en/online-battle/`）也能用，插件通过棋盘元素识别页面，不依赖语言。

## 安装

先构建（需要 Node.js 18+，没有外部依赖）：

```bash
node build.js
```

构建结果在 `dist/` 下，仓库里也已经提交了一份构建好的版本。

**方式一：Chrome / Edge 扩展（推荐）**

1. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择 `dist/extension` 文件夹。
4. 刷新 gomoku.com 页面。

**方式二：油猴脚本（Tampermonkey / Violentmonkey）**

新建脚本，把 `dist/gomoku-ai.user.js` 的全部内容粘贴进去并保存。

## 使用

页面右下角会出现“五子棋 AI 助手”面板，可以拖动标题栏移动位置。

| 控件 | 作用 |
|---|---|
| 关闭 / 提示 / 自动下棋 | 三种模式。提示模式只在棋盘上用红圈标出建议落点；自动模式会替你点击落子（绿圈）。 |
| 思考时间 | 每步搜索时间，0.3–6 秒。越长越强。 |
| 落子延迟 | 自动模式下算完后再等待的时间（带随机抖动），0–4 秒。 |
| 我方胜率 | 实时胜率（大字），下方是黑白双方胜率条和整盘胜率曲线；每一手之后都会更新，对方思考时也会计算。 |
| 上一手 | 最近一手棋让我方胜率变化了多少，例如“上一手 对方(白) J7：我方胜率 −8%”。 |
| 建议落子 | 坐标，列 A–O，行 15–1（左上角为 A15）。 |
| 评估 | 正数对我方有利；“必胜”表示已找到强制取胜手段。 |
| 胜率热图 | 在棋盘上标出候选点下了之后的我方胜率：前 10 个写数字，其余用小圆点；绿色表示和最佳着法差不多，黄、橙、红表示依次变差。标 × 的点是必败：下在那里之后对方有强制取胜手段（悬停可看到对方几步内成五）。 |
| 帮对手计算 | 对方回合时也替对方算一遍：紫色虚线圈是对方的最佳着法，紫边数字是对方下在各点后的“对方胜率”（× 为对方必败、“胜”为对方必胜），后续变化从对方那一手开始画；面板显示“对方回合 · 对方最佳 H10（对方胜率 43%）”，悬停显示“若对方下 X：对方胜率 …，我方 …”。对方有必胜手段时会红字提醒。只在“提示”模式生效，可在面板里关掉。 |
| 红色提示 | 当对方有活三、连续冲四等强制攻势、只有一两手能守住时，面板会直接列出这几手，例如“只有 I10、I6 能避免必败”。 |
| 鼠标悬停 | 悬停在任意空点上，面板显示“若下 H8：我方胜率 55%（−7%）”，即下在这里的胜率以及和最佳着法相比的变化；必败或必胜的点会写明几步内成五，例如“必败：对方 2 步内可强制成五”。不在候选表里的点会即时计算。 |
| 后续变化 | 用带编号的半透明棋子画出推荐着法之后双方的预计应对（最多 9 手），以黄框结束表示这条线能成五。 |
| 立即计算 | 重新计算当前局面。 |
| Alt+A | 在“提示”与“自动下棋”之间切换（在输入框里打字时不触发）。 |

设置保存在浏览器本地，下次打开自动恢复。胜率热图和后续变化只在“提示”模式显示；“自动下棋”模式只算推荐着法和胜率，不拖慢落子。

胜率是怎么来的：引擎的局面分数通过一条逻辑曲线换算成概率，曲线用本引擎 1200 盘自我对弈中约 2.2 万个局面的最终胜负拟合（`test/calibrate-winrate.js`，数据在 `test/data/winrate-samples.csv`）。它表示“双方都按本引擎的水平下”时的胜率，不是对真人对手的精确预测。五子棋规则下校准很好（各分段预测与实际相差约 3% 以内）；连珠在 35%–55% 区间对轮到走棋的一方略偏乐观。

## 工作原理

- `src/controller.js`：在页面主环境中运行。它从棋盘 DOM（`.board-intersection` 里的 `.black-stone` / `.white-stone`）读出局面，再从“玩家棋子”图标或棋盘的 `player-black/white` 类判断我方颜色。只有当回合提示等于 `i18n.t('Your Turn')`、且棋子数说明轮到我方时才会行动，所以观战时不会误点。落子方式是模拟点击对应交叉点；小屏幕上的“点两次确认”模式也会处理。
- `src/engine.js`：独立的 AI 引擎，在 Web Worker 里运行，不卡页面。
  - 每个空点、每个方向用 3^10 查表得到棋型（五、活四、冲四、活三……），并增量更新。
  - 迭代加深的 alpha-beta 搜索，配合置换表，以及冲四、活三的强制应对剪枝。
  - 双方都有 VCF（连续冲四）和 VCT（连续冲四 / 活三）威胁搜索，并带失败局面缓存。先找自己的必胜；对方有必胜手段时，只在能化解它的着法中选择。
  - 连珠规则完整实现：长连、四四（包括同一条线上的四四）、三三都判为禁手；“真活三”会递归判定；黑棋五连优先于禁手。
  - 分析模式：先给出推荐着法，再对最多 40 个候选点做全窗口搜索得到各自的准确分数（逐步加深），最后让引擎自己和自己把推荐着法之后的变化下出来。结果分三次逐步送回页面，所以红圈会先出现，热图和后续变化随后补上。

## 测试

```bash
node test/run-tests.js            # 128 项：战术题、增量状态一致性、连珠禁手（与独立参考实现对照）、时间控制
node test/analysis-tests.js       # 11 项：胜率换算、热图、后续变化、悬停评估、跨回合胜率一致性
node test/match.js --rule renju --games 20 --time 300                 # 对独立的基准 AI
node test/match.js --rule freestyle --games 20 --time 300 --opp v1:300 # 对上一版引擎
node test/controller-sim-delay.js 1000 3000 3000                       # 控制器模拟（假 DOM）
node test/controller-sim-opponent.js                                   # “帮对手计算”模拟
```

`test/repro/` 中是代码审查时用来复现问题的脚本。

## 说明

在线对战的对手是真人，并且有积分排名。用“自动下棋”代打排位对其他玩家不公平，也可能违反网站规则，账号有被处理的风险。建议在线对战用“提示”模式学习，或者在单人模式里使用自动下棋。
